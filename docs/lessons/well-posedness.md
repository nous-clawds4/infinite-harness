# Lesson: check that the question is well-posed

**Source:** David Strayhorn, 2026-10-11, 10:33 AM ET (relayed to Physics Lead in chat, recorded by Chief of Staff; not signed).
**Applies to:** every project and every rung of the harness.
**Companion:** [creative-tweaks.md](creative-tweaks.md).

## David's words

> If we ever find ourselves trying to answer a question whose answer feels elusive, we should consider whether the question itself is well-posed, meaning whether the question is well-defined, meaning all the terms and variables in the question are well defined... The resolution is to reject the question as ill-posed. Sometimes, ill-posed questions can sneak into a research program and poison the entire program with gibberish statements masquerading as physics. We need to develop the intuition to not let that happen, and the way to do that is to look for it deliberately, especially when we feel stuck.

## The example

In the physics project (P1), the Zeno-mass work raised the question "what is the physics at a Zeno state T that doesn't exist?" One framing treated continuing past such a state as possible new physics. The resolution: the state does not exist, so the question has no referent. Reject it as ill-posed; no new physics is needed.

## Practice

1. **When stuck, check the question first.** Before another attempt at an elusive answer, list every term and variable in the question and confirm each is defined in the record (a definition, a C-row, a node). Anything undefined, or with no referent, is a reason to suspect the question.
2. **Rejecting is a legitimate outcome.** "Ill-posed: term X is undefined" (or "has no referent") is a valid answer and should be recorded as one, with the term named.
3. **Look for it deliberately.** Lead agents add a well-posedness check to the briefs for pressure tests and external reviews: "Is every question this document answers well-posed? Name any term that is undefined or has no referent."
4. **In the Path 42 graph,** a question node shown to be ill-posed is closed with that reason, not left open for an answer.
